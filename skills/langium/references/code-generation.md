## Choosing the API

Everything comes from `langium/generate`.

| Use | When |
| --- | --- |
| `expandToNode` + `joinToNode` + `toString` | **Default.** Multi-line output composed from several functions. Indentation of nested parts is handled for you |
| `CompositeGeneratorNode` (`append`, `indent`, `appendNewLine`, `appendIf`) | Output built step by step with many conditions |
| `expandToString` | A small, self-contained string. Substitutions are aligned but not composable as nodes |
| `expandTracedToNode`, `traceToNode`, `joinTracedToNode` + `toStringAndTrace` | You need to map generated text back to DSL source (source maps, error mapping) |

All generator functions return `Generated` (`GeneratorNode | string | undefined`). `undefined` contributes nothing, which makes optional parts easy.

## Recipes

The examples use a domainmodel-like grammar:

```langium
Model: entities+=Entity*;
Entity: 'entity' name=ID ('extends' superType=[Entity:ID])? '{' features+=Feature* '}';
Feature: (many?='many')? name=ID ':' type=[Entity:ID];
```

### Template-based generator

Keep the generator a pure function from AST to `Generated`. Do file I/O elsewhere so you can test it. Based on `examples/domainmodel/src/cli/generator.ts` and `examples/statemachine/src/cli/generator.ts`.

```ts
import { expandToNode, joinToNode, toString, type Generated } from 'langium/generate';
import type { Entity, Feature, Model } from './generated/ast.js';

export function generateModel(model: Model): string {
    const fileNode = expandToNode`
        // generated by mydsl, do not edit

        ${joinToNode(model.entities, generateEntity, { appendNewLineIfNotEmpty: true })}
    `;
    return toString(fileNode);
}

function generateEntity(entity: Entity): Generated {
    // optional part: undefined renders nothing
    const ext = entity.superType?.ref ? ` extends ${entity.superType.ref.name}` : '';
    return expandToNode`
        export class ${entity.name}${ext} {
            ${joinToNode(entity.features, generateFeature, { appendNewLineIfNotEmpty: true })}
        }
    `;
}

function generateFeature(feature: Feature): Generated {
    const type = feature.type.ref?.name ?? 'unknown';
    return `${feature.name}: ${type}${feature.many ? '[]' : ''};`;
}
```

The nested `joinToNode` output is indented to the column of `${` automatically, and so is every line of a multi-line substitution.

### Control whitespace in templates

`expandToNode` applies these rules, which explain almost every "extra blank line" or "missing newline" problem:

1. The common leading indentation of the template lines is removed.
2. The first line is dropped if it is blank, and so is the last line if it holds only whitespace before the closing backtick.
3. A line whose last substitution is `undefined` or a generator node, and that otherwise holds only whitespace, is omitted when the substitution renders empty. End the line with `${''}` to force the line break.

`joinToNode(items, toGenerated?, options?)` options:

| Option | Effect |
| --- | --- |
| `separator` | inserted between non-`undefined` items, e.g. `', '` |
| `prefix`, `suffix` | fixed value or `(item, index, isLast) => Generated` per item |
| `appendNewLineIfNotEmpty` | `true` or 1 to 6 line breaks after each non-empty item |
| `skipNewLineAfterLastItem` | no trailing line break after the last item |
| `filter` | skip items while keeping their original `index` |

```ts
// a, b, c on one line
expandToNode`fn(${joinToNode(params, p => p.name, { separator: ', ' })})`;
// one item per line, with a blank line between items but not after the last
joinToNode(entities, generateEntity, { appendNewLineIfNotEmpty: 2, skipNewLineAfterLastItem: true });
```

Append a final newline with `.appendNewLine()` on the returned node. `NL` is a line break node, `NLEmpty` a line break that is skipped if the line is empty.

### Imperative building

Use `CompositeGeneratorNode` when the structure depends on many conditions:

```ts
import { CompositeGeneratorNode, NL, toString } from 'langium/generate';
import type { Entity } from './generated/ast.js';

export function generateEntityImperative(entity: Entity): string {
    const node = new CompositeGeneratorNode();
    node.append('export class ', entity.name);
    node.appendIf(entity.superType?.ref !== undefined, ' extends ', entity.superType?.ref?.name);
    node.append(' {', NL);
    node.indent(body => {
        for (const feature of entity.features) {
            body.append(feature.name, ': ', feature.type.ref?.name ?? 'unknown', ';', NL);
        }
    });
    node.append('}', NL);
    // indentation defaults to 4 spaces, pass a string or number to change it
    return toString(node, '\t');
}
```

`indent` also takes an array of children or `{ indentedChildren, indentation, indentEmptyLines, indentImmediately }`. `expandToNode` results are `CompositeGeneratorNode`s, so both styles mix freely.

### CLI generator

The `yo langium` CLI template (`packages/generator-langium/templates/packages/cli-example/src/`) and the examples use this shape. Load services with `NodeFileSystem`, build the document **with validation**, refuse to generate on errors, then write files.

```ts
// src/cli/cli-util.ts
import type { AstNode, LangiumCoreServices, LangiumDocument } from 'langium';
import { URI } from 'langium';
import * as fs from 'node:fs';
import * as path from 'node:path';

export async function extractDocument(fileName: string, services: LangiumCoreServices, root?: string): Promise<LangiumDocument> {
    const extensions = services.LanguageMetaData.fileExtensions;
    if (!extensions.includes(path.extname(fileName))) {
        throw new Error(`Expected a file with one of these extensions: ${extensions.join(', ')}`);
    }
    if (!fs.existsSync(fileName)) {
        throw new Error(`File ${fileName} does not exist.`);
    }
    // load every file of the workspace so cross-file references resolve
    if (root) {
        const rootPath = path.resolve(root);
        await services.shared.workspace.WorkspaceManager.initializeWorkspace([{ name: path.basename(rootPath), uri: URI.file(rootPath).toString() }]);
    }
    const document = await services.shared.workspace.LangiumDocuments.getOrCreateDocument(URI.file(path.resolve(fileName)));
    await services.shared.workspace.DocumentBuilder.build([document], { validation: true });

    // severity 1 is DiagnosticSeverity.Error
    const errors = (document.diagnostics ?? []).filter(d => d.severity === 1);
    if (errors.length > 0) {
        const lines = errors.map(e => `line ${e.range.start.line + 1}: ${e.message} [${document.textDocument.getText(e.range)}]`);
        throw new Error(`Validation errors:\n${lines.join('\n')}`);
    }
    return document;
}

export async function extractAstNode<T extends AstNode>(fileName: string, services: LangiumCoreServices, root?: string): Promise<T> {
    return (await extractDocument(fileName, services, root)).parseResult.value as T;
}
```

```ts
// src/cli/main.ts (adjust the language imports to your layout, e.g. the `my-dsl-language` package in a yo langium workspace)
import { Command } from 'commander';
import { NodeFileSystem } from 'langium/node';
import * as fs from 'node:fs';
import * as path from 'node:path';
import type { Model } from '../language/generated/ast.js';
import { MyDslLanguageMetaData } from '../language/generated/module.js';
import { createMyDslServices } from '../language/my-dsl-module.js';
import { extractAstNode } from './cli-util.js';
import { generateModel } from './generator.js';

export async function generateAction(fileName: string, opts: { destination?: string, root?: string }): Promise<void> {
    const services = createMyDslServices(NodeFileSystem).MyDsl;
    const model = await extractAstNode<Model>(fileName, services, opts.root);
    const destination = opts.destination ?? path.join(path.dirname(fileName), 'generated');
    const target = path.join(destination, `${path.basename(fileName, path.extname(fileName))}.ts`);
    fs.mkdirSync(destination, { recursive: true });
    fs.writeFileSync(target, generateModel(model));
    console.log(`Generated ${target}`);
}

const program = new Command();
program
    .command('generate')
    .argument('<file>', `source file (${MyDslLanguageMetaData.fileExtensions.join(', ')})`)
    .option('-d, --destination <dir>', 'output directory')
    .option('-r, --root <dir>', 'workspace root to load for cross-file references')
    .action(async (file, opts) => {
        try {
            await generateAction(file, opts);
        } catch (err) {
            console.error(String(err));
            process.exitCode = 1;
        }
    });
program.parse(process.argv);
```

`createMyDslServices` from the scaffold works without a connection. For a headless package with no LSP dependency, build the services from `createDefaultCoreModule` and `createDefaultSharedCoreModule` instead (see [project-setup.md](project-setup.md)).

### Test a generator

Parse with `parseHelper`, call the pure generator, compare text. From `examples/statemachine/test/generator.test.ts`:

```ts
import { EmptyFileSystem } from 'langium';
import { expandToStringWithNL } from 'langium/generate';
import { parseHelper } from 'langium/test';
import { describe, expect, test } from 'vitest';
import type { Model } from '../src/language/generated/ast.js';
import { createMyDslServices } from '../src/language/my-dsl-module.js';
import { generateModel } from '../src/cli/generator.js';

describe('generator', () => {
    const services = createMyDslServices(EmptyFileSystem).MyDsl;
    const parse = parseHelper<Model>(services);

    test('generates a class per entity', async () => {
        const document = await parse('entity A {} entity B extends A { many items: A }', { validation: true });
        expect(document.diagnostics).toHaveLength(0);
        expect(generateModel(document.parseResult.value)).toBe(expandToStringWithNL`
            // generated by mydsl, do not edit

            export class A {
            }
            export class B extends A {
                items: A[];
            }
        `);
    });
});
```

`expandToStringWithNL` uses the platform line separator, like `toString`, so the test passes on Windows too. More in [testing.md](testing.md).

### Generate from the language server

To generate from the editor, call the same generator from an `ExecuteCommandHandler` command (see the code lens recipe in [lsp-features.md](lsp-features.md)), or on save from a custom `DocumentUpdateHandler` in the shared module:

```ts
import { DocumentState, URI, type TextDocument } from 'langium';
import { DefaultDocumentUpdateHandler, type LangiumSharedServices } from 'langium/lsp';
import type { TextDocumentChangeEvent } from 'vscode-languageserver';
import type { Model } from './generated/ast.js';
import { generateModel } from '../cli/generator.js';

export class MyDslUpdateHandler extends DefaultDocumentUpdateHandler {
    constructor(protected readonly shared: LangiumSharedServices) {
        super(shared);
    }

    // defining this method makes the server advertise save notifications
    async didSaveDocument(event: TextDocumentChangeEvent<TextDocument>): Promise<void> {
        const uri = URI.parse(event.document.uri);
        await this.documentBuilder.waitUntil(DocumentState.Validated, uri);
        const document = this.shared.workspace.LangiumDocuments.getDocument(uri);
        if (document && !(document.diagnostics ?? []).some(d => d.severity === 1)) {
            const text = generateModel(document.parseResult.value as Model);
            // write `text` with node:fs, or send it to the client
        }
    }
}
// shared module: lsp: { DocumentUpdateHandler: (services) => new MyDslUpdateHandler(services) }
```

`DefaultDocumentUpdateHandler` does not define `didSaveDocument`, so declare it without `override`. In a browser language server there is no file system: return the text to the client instead. See [langium.org: generation in the web](https://langium.org/docs/learn/minilogo/generation_in_the_web/) for the idea, but use the APIs on this page.

### Tracing and source maps

Use the traced variants to record which DSL region produced which output region, then `toStringAndTrace`:

```ts
import { expandTracedToNode, joinTracedToNode, toStringAndTrace, traceToNode, type TraceRegion } from 'langium/generate';
import type { Entity, Model } from './generated/ast.js';

function generateEntityTraced(entity: Entity) {
    return expandTracedToNode(entity)`
        export class ${traceToNode(entity, 'name')(entity.name)} {
            ${joinTracedToNode(entity, 'features')(entity.features, f => `${f.name}: ${f.type.$refText};`, { appendNewLineIfNotEmpty: true })}
        }
    `;
}

export function generateWithTrace(model: Model): { text: string, trace: TraceRegion } {
    return toStringAndTrace(joinTracedToNode(model, 'entities')(model.entities, generateEntityTraced, { appendNewLineIfNotEmpty: true }));
}

// find the innermost source region for an offset in the generated text
export function findSource(trace: TraceRegion, offset: number): TraceRegion | undefined {
    if (offset < trace.targetRegion.offset || offset >= trace.targetRegion.end) {
        return undefined;
    }
    for (const child of trace.children ?? []) {
        const found = findSource(child, offset);
        if (found) {
            return found;
        }
    }
    return trace;
}
```

Each `TraceRegion` has `targetRegion` (in the output), `sourceRegion` (`fileURI`, `offset`, `end`, `range`), and `children`. Convert it to a standard source map with a library such as `source-map` if you need one. Tracing needs nodes with a CST (`$cstNode`), which documents built by Langium always have. The `-If` variants (`expandTracedToNodeIf`, `joinTracedToNodeIf`, `traceToNodeIf`) add a condition.

## Best practices

- **Generate only from validated, error-free documents.** Build with `{ validation: true }` and stop on errors. Generators then rarely see unresolved references or partial ASTs.
- **Still guard references.** Use `ref?.name` with a fallback, or `$refText` when you only need the written name. For multi-references (`[+Type:ID]`) iterate `items` (each has `ref`); there is no `ref` on the multi-reference itself.
- **Pure generator, separate I/O.** Return `Generated` or `string` from the AST; write files in the CLI. This makes tests trivial and lets the language server reuse the generator.
- **One function per AST type,** composed through `${...}` and `joinToNode`. Avoid string concatenation with manual `'\n'` and indentation.
- **Load the workspace for multi-file models.** A single `getOrCreateDocument` does not load imported files; use `WorkspaceManager.initializeWorkspace` first.
- **Use `AstUtils.streamAllContents` or typed properties** to collect nodes, not hand-written recursion.

## Pitfalls

| Symptom | Fix |
| --- | --- |
| Output has `undefined` in it | A reference didn't resolve (`ref` is `undefined`) or an optional property is missing. Validate first and guard with `?.` and a fallback |
| Extra blank lines or missing line breaks | See the whitespace rules: use `appendNewLineIfNotEmpty`, `skipNewLineAfterLastItem`, or end a line with `${''}` to force it |
| Nested block not indented | The substitution was turned into a string with `toString` or template literal concatenation before embedding. Embed the node itself |
| Cross-file references unresolved in the CLI | Only the given file was loaded. Initialize the workspace with the project root before building |
| Generator runs on a broken file | `build` was called without `{ validation: true }`, or diagnostics weren't checked. Linking errors are errors too |
| Tests pass on Linux, fail on Windows | Expected text uses `\n` while `toString` uses the platform EOL. Compare with `expandToStringWithNL` or normalize with `normalizeEOL` |
| `toString` prints `[object Object]` | The value is not a `Generated` (for example an AST node). Pass the name or a generator node |
| `expandToNode` or `joinToNode` not found when importing from `langium` | Generator APIs are only exported from `langium/generate` |
